# 收斂契約 — README.zh-TW.md 中文行文潤飾

凍結時間：2026-08-27。凍結後只有使用者能修改本契約。

## 終態（一句話）

`README.zh-TW.md` 全文讀起來像中文母語者所寫，語氣自章節之間一致；同時結構、術語、程式碼區塊、表格、數字與 `README.md` 逐節對齊，事實內容零變動。

## In-scope 交付物

1. 六個分段的中文散文潤飾（第一輪，haiku 六名並行）。
2. 全文語氣統一與跨段一致性複潤（第二輪，sonnet 單名持棒）。
3. 合併回單一 `README.zh-TW.md`、機械驗收、commit、push origin/main。

## Out-of-scope（本輪不做，發現一律入 parking-lot）

- 修改 `README.md`（英文版）任何一個字元。
- 變更任何事實陳述、數值、量測結果、版本號、檔案路徑、識別碼（AD-NNN / G-NNN / TC-NNN）。
- 新增、刪除、重排任何章節或標題；標題文字本身不潤飾。
- 修改任何程式碼、設定、其他文件。
- 統一術語譯法以外的用語改革（例如把既有譯名整批換成別的譯名）。

## 潤飾尺度（使用者裁定）

允許：調整中文語序與用詞、把英文長句拆成兩句中文、補上中文習慣的主詞、去除「被動式堆疊 / 的的不休 / 逐字對譯」的譯文腔。

禁止：改動標題行、程式碼區塊（```fence``` 內）、表格的欄位結構、行內程式碼 `` ` `` 包住的識別碼、任何數字與單位、技術名詞原文（tier-1、MethodChannel、ImageProvider 等保留原文）。

## 逐條驗收條件（機械可查）

| # | 條件 | 檢查方式 |
|---|---|---|
| AC1 | 合併後所有 Markdown 標題行（`^#{1,6} `）與原檔逐行完全相同 | 抽出標題行 diff 為空 |
| AC2 | 所有程式碼區塊（fence 內全部內容）與原檔完全相同 | 抽出 fence 內容 diff 為空 |
| AC3 | 表格列數（`^\|` 開頭行數）與原檔相同 | 計數相等 |
| AC4 | 全文數字＋單位 token 集合與原檔相同 | 正規表達式抽取後排序 diff 為空 |
| AC5 | 識別碼 token 集合（`AD-\d+`、`G-\d+`、`TC-\d+`、`\w+\.dart`、`lib/...`）與原檔相同 | 抽取後排序 diff 為空 |
| AC6 | 合併檔通過 roundtrip：六段串接無遺漏、章節順序不變 | 標題序列比對 |
| AC7 | diff 非空且散文實質改寫（非僅空白變動） | `git diff --stat` 且抽查 |
| AC8 | 主對話逐段抽查至少 6 處（每部分 ≥1），確認語氣自然、無新增譯文腔 | 主對話親自 Read 抽查紀錄 |

| AC9 | Markdown 區塊結構（空行、標題、表格、清單縮排層級、引用、程式碼區塊）序列與原檔相同；散文重新斷行不算結構變動 | `scripts/tmp/readme-polish/structcheck.py` diff 為空 |

AC1–AC6 由驗收腳本 `scripts/tmp/readme-polish/verify.py` 機械裁決；AC9 由 `structcheck.py` 裁決；AC7–AC8 由主對話親自判讀。

AC9 於第一輪進行中補入（2026-08-27）：AC1–AC6 對「掉一行空行」「清單項被併進段落」完全不可見，而散文重新斷行會讓逐行 diff 失去意義，故需獨立的結構序列比對。此為加嚴，非放寬；兩支腳本均已在注入違規的情況下實測亮紅燈後才採用。
