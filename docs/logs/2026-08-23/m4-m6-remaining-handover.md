## 2. M5 — RAW 的全解析度 tier-2（選配）

### 設計權威原文
「以 M3 的記憶體數字為閘。緊的話直接不做——視窗解析度已經勝過今天的『抵達時什麼都沒有』。」

### 那個數字現在存在了，但**還不足以開閘**
- round-2 實測：kernel max RSS **996,392,960 bytes = 950.2 MiB**，相對判準**通過**（M3 之前基線 1,043,218,432 bytes = 994.9 MiB）。
- **但那次量測掃的是昂貴（無內嵌預覽）樣本組**，也就是九格 tier-1 保證**不成立**的那一組。便宜（有預覽）樣本組——每項佔兩個 ImageCache 項、保證確實成立、記憶體上真正昂貴的那一組——**至今未量測**。
- **所以在做便宜樣本組的量測之前，不要用 950.2 MiB 去決定 M5 做不做。** 那個數字不代表 round 2 的真實成本。

### 開閘前必做順序
1. 先做**應用內版本戳記**（見 §4 P-2）。
2. 再做**便宜樣本組的 RSS 量測**（見 §4 P-1）。
3. 拿那個數字才有資格判斷 M5。

### 兩個一定會絆到人的地雷
1. **`PhotoSource.probe()` 是刻意保留的一行投影**，它疊在 `probeSource()` 之上，存在的唯一理由是讓 hash 凍結的測試檔 `test/dng_nav_probe_m3_test.dart:147,:180` 能繼續編譯（該處直接拿它跟 `SourceCost` 比對）。**它按設計就是零生產呼叫點。不要「順手清掉」。** 要移除必須先取得使用者對修改凍結檔的授權。

## 5. 你必須知道的既有約束（違反其中任一條會靜默弄壞東西）

1. **兩個快取常數以相反樣本組計算，不可互相驗算**——`imageCacheMaxBytes` 768 MiB 照便宜組算，`kPayloadByteBudget` 224 MiB 照昂貴組算。想「簡化」這一對的人會靜默弄壞其中一個。見 `memory.md` AD-019。
2. **`kTierTwoRadius`（2）與 `kExpensiveStartupRadius`（1）不得合併回一個常數**。合併會把冷啟動安定時間從約 25 秒推到約 42 秒，而且**看起來像忠實實作**。`test/image_preload_window_test.dart` 有一條 killer test 專門守這件事。見 `memory.md` AD-018。
3. **tier-1 與 tier-2 必須用同一個 `bytes` 物件識別與同一組寬高參數建構**（`tierOneProviderFor` / `fullSizeProviderFor`）。三者全中才是 `ImageProvider` 快取命中；不符會造成靜默的重複解碼。
4. **快取層不知道也不能知道自己裝的是 encoded bytes 還是 RGBA**。可機械檢查：`grep -c "EncodedPayload\|PixelPayload" lib/services/photo_payload_cache.dart` 必須是 **0**（設計權威 D4）。
5. **三個凍結測試閘門**（改動前需授權）：`scripts/tmp/dng_nav_probe_test.dart` `05565d33…`、`test/image_preload_controller_m3_amend3_test.dart` `fcdd564e…`、`test/dng_nav_probe_m3_test.dart` `59b1f3c7…`（**注意：最後這個已於 `d87d1d5` 重新錨定，舊值 `be3a595d…` 已作廢**）。
6. **`local_data/` 在 .gitignore**。新 worktree 沒有樣本，受樣本保護的測試會帶 `skip:`——**跳過看起來像通過**。先把樣本唯讀 symlink 進來，並且**先跑未變異的測試證明它真的執行過**，才可以相信任何紅燈。
7. **檔案 mtime 不能用來判斷樣本來源**：好幾個最新的 DNG 帶著 2024 年的 mtime，`ls -t` 排出過兩次錯誤清單。
8. **樣本組正典**：**26 個檔案，13 個昂貴、13 個便宜**。昂貴組是十二個 `2024-07-*` 加上 `IMG_20251112_092839.dng`（一個**舊**樣本但實測昂貴）；便宜組是 `2026-*` 系列。曾有兩個人各自獨立弄錯成 14/12。

## 6. 儀器紀律（本輪實地踩到，會製造出可信的假結果）

1. **退出碼一律讀 artifact 內自行捕獲的 `$?`。** 不要讀背景任務通知（曾對一次真實回傳 1 的執行回報 0——那是包裝層的碼），也不要用 `${PIPESTATUS[0]}`（在本環境不展開，已確認可重現）。
2. **量測前先證明 binary 含有受測程式碼，用「觀察到的建置事件」而非時間戳**：記下建置前的 HEAD 與工作區狀態、要求建置日誌顯示真實編譯與真實 `$?`、要求產物在你觀察到的那段時間窗內被改寫。曾有 release binary 比受測程式碼早 78 分鐘。
3. **`stat` 讀 macOS `.framework` 讀到的是 symlink 本身**——用 `stat -L` 或直接指向 `Versions/A/`。建置成功後 `App.framework/App` 仍會顯示舊時間。
4. **不要用「從 binary grep 常數」證明新鮮度**：`234881024` = `0x0E000000`、`805306368` = `0x30000000`，在 6.2 MB 的 snapshot 裡必然隨機命中。**不可能失敗的檢查比沒有檢查更糟。**
5. **`flutter test` 的進度行只有在 `-j 1` 下可靠**；宣告數 grep 會低估執行數（迴圈／group 產生的測試宣告一次執行多次）。**要預註冊的是「執行數」**。本套件目前執行數為 **238**。
6. **前景建置有自動 90 秒通道**（本專案 release 建置實測 33 秒）。背景分離通道需要使用者核發 token。**先試前景。**
