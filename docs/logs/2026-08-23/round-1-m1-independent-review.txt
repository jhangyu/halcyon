FINDINGS (none blocking)
F1 [Medium, test strength] The dpr half of the M1 requirement has no discriminating assertion.
   Evidence: mutation B (cap = 32, dpr ignored) is GREEN. Per round-1-m0-handoff "Structural
   findings" #2, that gate is decorative for this capability. Real defect class left open:
   a future refactor dropping the dpr factor ships half-resolution (blurry) thumbnails on every
   retina display and no test fires. Fix: add a second case at dpr 1.0 asserting the decoded
   longest edge EQUALS 32 (or parameterize dpr over {1.0, 3.0} and assert the edge tracks it) —
   an upper bound alone can never catch under-sizing.
F2 [Low, spec accuracy] "aspect within 1%" is a property of the chosen fixture, not of the
   implementation. Counterexample I produced: dpr 1.5, source 200x133 (a plain 3:2 photo at the
   native 200px thumbnail cap) -> decoded 48x31, 2.97% aspect error, from Flutter's integer
   truncation (targetHeight = targetWidth ~/ aspectRatio). This is not the exact-policy squash
   (which is 100% off) and BoxFit.cover in a 32x32 box hides it, so the shipped behavior is fine;
   the AC text is over-claimed. Record the bound as "no distortion beyond integer rounding".
F3 [Low, perf] sidebar_view.dart:281 uses MediaQuery.of(context).devicePixelRatio, which
   registers a dependency on the WHOLE MediaQueryData. SidebarView had no MediaQuery dependency
   before this diff (grep: only main_detail_view.dart:257 did). Every MediaQueryData change
   (desktop window resize, text scale, insets, brightness) now rebuilds the entire sidebar list.
   Fix: MediaQuery.devicePixelRatioOf(context) (media_query.dart:1652), aspect-scoped.
F4 [Info] cap = (32*dpr).round() has no >0 guard. Image.memory asserts cacheWidth > 0; the raw
   ResizeImage path does not. dpr < 0.016 would yield cap 0 and a zero-size decode target.
   Unreachable on supported platforms; noted only because the assert was dropped with the
   named constructor.

   byte-identical (md5 b338bc634415b14cb6859903a6fa8f12), including the "00:00" timing prefixes.
